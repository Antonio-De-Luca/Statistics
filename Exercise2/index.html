CRYPTOGRAPHIC ANALYSIS

Similarities & Differences

Comparing the Caesar cipher with a secp256k1-based encryption scheme.

1. Encryption and Decryption

Caesar: Encryption shifts every letter by a fixed number of positions. Decryption reverses the shift using the same secret key.

secp256k1: The elliptic curve establishes a shared secret through ECDH. A key-derivation function derives a symmetric key, which encrypts the message using AES-GCM. Decryption derives the same key and verifies the authentication tag before recovering the plaintext.

2. Key Space

Caesar: There are only 26 possible shifts for the English alphabet, including the ineffective zero shift. An attacker can test every key almost instantly.

secp256k1: The private key is a valid scalar in the range from 1 to n − 1, where n is the curve's subgroup order. This gives approximately 256 bits of key space, or about 2256 possible private keys. The effective classical security level is approximately 128 bits, not 256 bits.

3. Statistical Properties

Caesar: Preserves letter frequencies and patterns. Common letters remain common, repeated letters remain repeated, and word lengths are unchanged. Frequency analysis can reveal the plaintext.

secp256k1 + AES-GCM: With secure key generation and correct nonce handling, the ciphertext does not reveal ordinary plaintext letter-frequency patterns. AES-GCM also detects unauthorized modifications. Ciphertext length and protocol metadata may still reveal information.

4. What They Have in Common

Both transform readable plaintext into ciphertext and require the appropriate secret information to recover the message. Both depend on correct key handling, but their security foundations are fundamentally different.

Conclusion

Caesar provides only elementary obfuscation and is vulnerable to brute-force attacks and statistical analysis. A properly implemented secp256k1-based scheme combined with AES-GCM provides modern cryptographic security, subject to sound key management, authenticated public keys, and correct protocol design.

Important distinction: secp256k1 is an elliptic curve, not a standalone encryption algorithm. ECDH establishes a shared secret; a key-derivation function and a symmetric cipher such as AES-GCM perform the actual message encryption and decryption.
SECURITY ANALYSIS

Vulnerabilities

Two practical attacks demonstrate how a weak key space can compromise encryption, using statistical analysis for Caesar and exhaustive search for restricted elliptic-curve keys.

1. Statistical Cryptanalysis of the Caesar Cipher

English text has a characteristic letter-frequency distribution. For example, E, T, A, and O occur more frequently than J, Q, X, and Z. The Caesar cipher preserves these frequencies, merely shifting which letters appear most often.

The attack tries every possible decryption shift and scores each candidate against the expected English letter frequencies using the chi-squared statistic. The candidate with the lowest score is selected as the most likely plaintext.

Enter a sufficiently long English passage in the message field above to test the attack.

2. Brute-Force Attack on Restricted secp256k1

In a real secp256k1 implementation, the private key is selected from an enormous range. For this experiment, Bob's private key is deliberately restricted to integers between 1 and 5,000.

The attacker enumerates candidate private keys, calculates each candidate public key, and compares it with Bob's known public key. If a match is found, the attacker can derive the ECDH shared secret and decrypt the message.

This experiment generates a fresh toy key pair and ciphertext, then attempts to recover the private key.

3. Comparing the Attacks

Caesar — statistical cryptanalysis

The attacker exploits the statistical structure of natural language. All 26 shifts can be tested, and letter frequencies help rank the candidates. The attack can fail on short, unusual, or non-English messages.

Restricted ECC — exhaustive key search

The attacker exploits an artificially small private-key space. Each candidate is checked against the public key, without needing to infer anything from the message's letter frequencies. Once the private key is recovered, the attacker can derive the encryption key.

Properly configured ECC

The secp256k1 private scalar has approximately 256 bits of representation and about 2256 possible valid values. Exhaustive search is therefore infeasible with known classical computing technology. Generic elliptic-curve discrete-logarithm attacks have an estimated work factor on the order of 2128 group operations, which is still infeasible in practice.

Conclusion

The Caesar cipher fails because its key space is tiny and its ciphertext leaks language statistics. The toy ECC scheme fails because its private key is selected from an insecurely small range. These are different weaknesses: one exploits predictable plaintext statistics, while the other exploits insufficient key entropy.

Experimental limitation: results depend on message length, language, and the distribution of letters. The restricted ECC demonstration is intentionally insecure; it must not be interpreted as an attack on a properly configured secp256k1 implementation.
